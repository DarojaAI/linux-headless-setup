## Finding 3: `linux-desktop-seed` hygiene issues

### Evidence

Committed to the repo root:
- `server-ip.txt` — contains `178.105.6.42` (a live server IP, used as the test/head env per `openclaw-gateway/docs/architecture.md`)
- `server-name.txt` — contains `ubuntu-8gb-hel1-2` (the server hostname)

`.gitignore` shows:
```
# Private documentation (sensitive environment info)
docs-private/

# Local Claude settings (contains test server IP)
.claude/settings.local.json

# Local test scripts (contains sensitive server info)
tests/test-usability.sh
```

The pattern: the operator / agent discovered leaks and added them to `.gitignore` *individually*. `server-ip.txt` and `server-name.txt` were either missed or considered "OK because the repo is private."

`linux-desktop-seed` is **private** (`gh repo view --json isPrivate` → `true`). So this is a hygiene issue, not a public leak.

### Why this matters

- The IP and name are *deployed environment identifiers* and should live in CI/secrets, not the repo. Even private repos get cloned to laptops and CI runners.
- A future operator who opens this repo will copy the pattern. "Oh, IPs in txt files is fine here, must be the convention." It's not.
- The `docs-private/` gitignore pattern suggests there was a more general "private docs" directory that got nuked but the txt files survived.

### Action

- **P1 fix:** Remove `server-ip.txt` and `server-name.txt` from the repo. Replace with a `docs/DEPLOYED-ENVIRONMENTS.md` that says "for deployed environment IPs and hostnames, see [your-secret-store / your-deploy-target]." Don't hardcode anything.
- **Bigger fix:** Add a docs audit pass — `linux-desktop-seed` is one of the better-documented repos, but its `.gitignore` is a tell that other things have leaked. Run the `dev-nexus` `docs-audit` skill against it, or my own version.
- **Open question for operator:** OK to do this as a PR in linux-desktop-seed, or just flag?
