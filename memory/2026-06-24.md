## What surprised me

- The boundary doc's own diagram shows `DevNexus -.->|can call for verification| VmOps` and `DevNexus -.->|can query for context| MCP` with *dashed* arrows — those are aspirational too, and the doc says so. I drew them as if they were real in my CTO diagram. The audit caught it; the doc's own notation was the right hint and I missed it.

- The boundary doc still lists `dependency-orchestrator` and `pattern-miner` as live A2A consumers (lines 263, 272). Both repos are archived. The doc was last touched 2026-06-09 (per its header), so the staleness is only ~2 weeks old but it's a real P0-adjacent issue — the contract doc references dead code as live. The operator caught this; I would have missed it if I'd just shipped the diagram.

- The `mcp-tooling/runtime/base.py:4-9` "shape mirrors dev-nexus's BaseSkill" line is the closest thing to a real cross-repo coupling in the triad. It's a *parallel interface*, not a runtime call — but it's also a load-bearing signal: when `mcp-tooling` adds a new tool, the shape matches what `dev-nexus`'s skills produce. That's worth a note in the CTO summary, but it doesn't deserve an edge in the Mermaid.

## What I learned (load-bearing)

1. **The triad is mostly a contract, not a wire.** Only one of the three edges has runtime evidence today. The contract *aspirationally* defines the others but they aren't implemented. The right CTO framing is "one runtime integration, two declared interfaces."

2. **Diagram labels matter more than edges.** "query / verify" implied a wired integration that doesn't exist. "declared (A2A+MCP), no runtime import observed" is honest. The lesson: when drawing an architectural diagram for an audience, prefer boring true labels over interesting false ones.

3. **Boundary docs rot the same way README docs do.** dev-nexus#1168 is exactly the kind of issue the org's own boundary contract says I should file rather than PR directly. Followed the contract; filed the issue.

4. **The verify-writes rule from AGENTS.md applied here too.** I'd claimed I saved a file in the prior turn; I hadn't. The "verify before claiming done" habit catches this kind of bug at one extra tool call's cost.
