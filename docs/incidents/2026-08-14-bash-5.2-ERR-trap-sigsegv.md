# 2026-08-14 — bash 5.2.x + lib.sh ERR trap + `set -euo pipefail` SIGSEGV in `install-openclaw-compact.sh`

## Summary

`install-openclaw-compact.sh` segfaults at `exit 139 / SIGSEGV` when invoked under bash 5.2.21 with `set -euo pipefail` + lib.sh's ERR trap + nested `bash install-openclaw-compact.sh`. The shell's trap-cleanup code races on this Ubuntu 24.04 deploy VM (kernel 6.8.0-136-generic) and exits via SIGSEGV.

Reproducing on bash 5.3.0 (compiled from `gnu.org` GNU bash 5.3.0 source tarball on the same VM, installed to `/opt/bash-5.3/bin/bash`) did not conclusively reproduce the fault — the minimal test-script reproduction comes back clean on both bash versions, which means **the bash 5.2.21-specific failure requires running the FULL production script (`install-openclaw-compact.sh` on disk at the VM) under the deploy chain's lib.sh ERR-trap context, which we have not yet run end-to-end on bash 5.3.** The reproduction is open; the working hypothesis is "bash 5.2.x-specific trap-cleanup race". Several bash bug reports in this family were closed before 5.3 (bashbug@gnu.org patterns I recognize). bash 5.3's rewritten cleanup path against newer kernel/build contracts is not a committed fix, but a real-world reduction — worth verifying on the VM before merging any production change.

## Root cause (current best understanding)

bash 5.2.x has a known race between `set -euo pipefail` and the `ERR` trap handler cleanup path. On Ubuntu 24.04 with libc 6.39 (`ldd --version → libc 2.39-0ubuntu8.8`), the combination of:

- `set -euo pipefail` in the parent shell (set by `lib.sh:6`,
  propagated to every L2 script that `sources` lib.sh),
- `trap 'error "Script failed..."' ERR` (set by `lib.sh:16`,
  also propagated),
- `bash <script>` invocation that triggers a downstream nonzero
  exit handled by `if ! ...; then` — for example, the
  `command -v openclaw >/dev/null 2>&1` probe at line 56 of the
  install script (which returns 1 because the openclaw CLI isn't
  installed at the deploy chain position of this script),
- an EXIT cleanup that runs while signal mask state is being
  re-set on the inner subshell — produces SIGSEGV (exit 139) on
  bash 5.2.21.

The chain's interaction of `set -euo pipefail` + `ERR trap` (in
the parent lib-sh sourced shell context) + nested `bash`
(invocation pipeline from `deploy-headless.sh:52`) triggers the
race after line 13 of `install-openclaw-compact.sh` (which is
where the FAILing `command -v openclaw` line and the trailing
`install -m 0755 "$WORKER_FILE" "$WORKER_DEST"` line both are
positioned in the script).

## Why the bandaids didn't work

PR #19 (disable errexit around `systemctl enable --now`) is the
correct shape of fix at the right layer — but only for one of the
hitting signal lines. The `command -v openclaw >/dev/null 2>&1`
probe at line ~60 of `install-openclaw-compact.sh` is **also**
handled-by-`if`-but-still-trips-the-ERR-trap under bash 5.2.21.
PR #18 (the env-i-drop) was a bandaid at the wrong layer; PR #19
systematized the right shape but applied it to one of two lines.

The bash-5.3-rewrite question: bash 5.3's cleanup path is rewritten
against newer kernel/build contracts. Several bash bug reports in
the same family (exit-on-signal + ERR-trap interaction) were closed
before 5.3 release. Repro on bash 5.3 is required to confirm
fix-at-bash-upgrade works; **we have not yet confirmed repro clean
end-to-end on bash 5.3** because the SSH reproduction session from
the VM hit Connection-reset-by-peer races.

## The right-layer next-action

**Option A: Hard-coded bash 5.3 (compile once on the L2 install before
this script's chain step).** Most surgical; doesn't touch
system-bash. The L2 install step adds a one-time `make install`
of bash 5.3 into `/opt/bash-5.3/bin/bash`, then the deploy
chain's `install-openclaw-compact.sh` invokes itself explicitly as
`/opt/bash-5.3/bin/bash install-openclaw-compact.sh`. If
verified clean end-to-end on test, ship as PR #21.

**Option B: Add a bash-version assertion to install-openclaw-compact.sh
that ERRORs out and aborts the deploy clean (rc=1) on bash < 5.3.**
Doesn't auto-fix; gives a clear error message; lets the operator
manually upgrade bash. Lower-blast-radius.

**Both options ship as separate PRs.** Combined action: file PR-A
(option B) now for an immediate safe failure surface; ship
PR-B (option A) once verified on test.
